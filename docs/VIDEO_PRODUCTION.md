# Техническое задание: производство видео «Химия просто»

Статус: версия 0.1 задания на реализацию. Числа экспортного профиля и длительности коротких видео ниже — предложенные рабочие настройки, не требования Instagram и не утверждённые владельцем параметры.

## 1. Результат

Получить понятный образовательный ролик: условие → смысл решения → действия → ответ → короткое приглашение на курс.
Одна единица короткого контента проверяет один навык. Ученик должен успеть прочитать данные и понять, почему применена формула.
Не превращать видео в набор быстро меняющихся слайдов с озвученным ответом.

Вход: заполненный templates/REEL_BRIEF.md, проверенные решение и текст, сведения об источнике.
Выход: MP4, редактируемые исходники, озвучка, субтитры, обложка, текст публикации и команда повторного рендера.

## 2. Рабочие профили

Предложенный профиль Reels: вертикальный 1080×1920, 30 кадров/с, MP4 H.264 + AAC, ориентир 35–60 секунд. Если решение длиннее — сократить тему или увеличить длительность, а не ускорять речь до непонимания.
YouTube: горизонтальный 1920×1080, 30 кадров/с, 7–10 минут по решению владельца. Не растягивать короткий сценарий; добавить смысл, несколько примеров и самостоятельную паузу.
Перед публикацией сверить актуальные требования платформ. Пробный экспорт просмотреть на телефоне.

## 3. Сценарная структура короткого ролика

Предложенная структура на 45–60 секунд:
- 0–4 с: конкретная задача или типичная ошибка без ложных обещаний.
- 4–10 с: условие с единицами и вопросом.
- 10–20 с: почему подходит выбранный метод.
- 20–40 с: последовательные действия; каждый переход виден.
- 40–50 с: ответ с единицами и короткая проверка.
- Последние 3–5 с: «Готовишься к ЕНТ по химии? Напиши в личные сообщения — расскажем о курсе».
Это шаблон. Реальное время подгонять по фактической длительности озвучки, не обрезая пояснения.
Не заявлять текущие свободные места, цену, гарантию балла или открытый набор без подтверждения владельца.

## 4. Три варианта пилота

A. Спокойный: чистый фон, формула по центру, плавное последовательное появление, голос репетитора.
B. Динамичный: та же задача, больше кратких акцентов, смена крупности, выделение ключевого числа; все шаги остаются читаемыми.
C. Аналогия: та же задача и полный ответ, краткое бытовое сравнение, затем строгие обозначения. Проверить границы аналогии, не закреплять неверную модель.

Для сравнения сохранить одинаковыми задачу, результат, ключевые шаги и призыв. По возможности один голос. Менять подачу и ритм.
Владелец выбирает по понятности, удобству чтения и ощущению бренда; просмотры позже могут дать дополнительную оценку.

## 5. Экран и формулы

Предложенный дизайн до утверждения: светлый фон, тёмный текст, один цвет для величин, другой для результата. Не утверждать палитру как уже согласованную.
В каждый момент — одна основная мысль. Появление формулы синхронизировать с фразой.
Формулы создавать текстом, вектором или математическим рендером; не генерировать растровую картинку формулы как источник точной записи.
Проверять индексы, степени, заряды, знаки реакций, скобки, единицы. Индекс и коэффициент должны отличаться.
Субтитры не закрывают решение. Закладывать внутренние поля и проверять наложение интерфейса приложения при предпросмотре. Точные безопасные области зависят от интерфейса.
Не обозначать смесь как молекулу; не применять молярный объём без условий; символы величин использовать последовательно.

## 6. Голос и субтитры

Русская естественная озвучка, ясные паузы перед вычислениями. Не имитировать голос конкретного человека без разрешения.
Текст для синтеза отделить от экранной записи: «эн равно эм, делённому на молярную массу» может потребовать редакции для естественной речи; лучше «Количество вещества находим: массу делим на молярную массу».
Словарь произношения: ЕНТ, моль, грамм на моль, степени десяти, названия веществ. Формулы не отдавать синтезатору наугад.
Прослушать каждый результат: ударения, числа, пропуски, обрыв слов, шум.
Субтитры сверять по готовому аудио; автоматически полученная расшифровка требует проверки терминов. Предпочитать короткие смысловые строки.
Фоновая музыка необязательна; она не должна мешать речи. Использовать материалы с подходящими правами.

## 7. Реализация

Стек пока не выбран. Можно рассмотреть программную анимацию, таймлайн-редактор или их сочетание. Выбирать по качеству формул, повторяемости рендера, доступности озвучки и времени работы.
Не считать наличие внешнего API доказанным. Проверить инструменты среды и официальные инструкции до установки и реализации.
Минимальный цикл: текст и проверка → раскадровка → голос → измерение длительности → тайминг сцен → анимация → субтитры → экспорт → просмотр → исправления.
Зависимости и команды записать после фактической реализации. Не добавлять неработающий README со «сгенерировать видео» без проверенной команды.
После первого принятого ролика вынести бренд, шрифты, голос и финальный экран в общую конфигурацию.

## 8. Организация файлов после реализации

Предложение:
content/reels/<id>/brief.md — тема и происхождение
content/reels/<id>/script.md — экран, озвучка, тайминг
content/reels/<id>/solution.md — полное проверенное решение
content/reels/<id>/review.md — результат проверки
src/ — код после выбора стека
assets/ — разрешённые статические материалы
exports/ — итоговые рендеры вне обычной истории Git или через выбранное хранилище
В начале репозитория этих готовых файлов и кода ещё нет: это структура для следующего этапа.

## 9. Масштабирование

Пять коротких роликов в неделю производить пакетно после утверждения пилота: проверить пять задач → пять сценариев → озвучка → рендер → просмотр → утверждение Мансуром.
Не переносить ошибки одного шаблона во все ролики. Формулы и числовые ответы проверять для каждой задачи.
Материалы курса и ролики связывать идентификатором навыка/темы, а не только красивым заголовком.
Длинный ролик строить из объяснения темы и разных примеров, не из механической склейки пяти Reels.

## 10. Приёмка

Использовать QUALITY_CHECKLIST.md. Минимальный результат пилота: видео реально открывается, речь и формулы синхронны, ответ верен, решение читается с телефона, нет утверждений о неподтверждённых условиях курса.
Статус «готово к публикации» выставлять только после просмотра и утверждения владельцем.
